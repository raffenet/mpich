# AGENTS.md - Agent Development Guide for MPICH

This file provides essential information for agentic coding assistants working with the MPICH codebase. MPICH is a high-performance implementation of the MPI standard, requiring careful attention to portability, performance, and coding standards.

## Build Commands

### Standard Development Build
```bash
# Initial setup (from git checkout)
./autogen.sh

# Configure for development
./configure --enable-g=all --enable-fast=O0

# Build with parallelism
make -j$(nproc)

# Install (optional)
make install
```

### Build Variants
```bash
# Optimized build
./configure --enable-fast=03,ndebug --disable-error-checking

# Debug build with memory checking
./configure --enable-g=mem,dbg --enable-g=meminit

# Coverage build for testing
./configure --enable-coverage
make coverage
```

### Code Quality Commands
```bash
# Format code according to MPICH standards
maint/code-cleanup.bash filename.c

# Format entire directory
find . -name "*.c" -exec maint/code-cleanup.bash {} \;

# Install pre-commit hook
ln -s ../../maint/hooks/pre-commit .git/hooks/pre-commit

# Spell check files
maint/spellcheck.sh filename.c

# Check copyright notices
maint/check_copyright.bash
```

## Testing Commands

### Running Tests
```bash
# Full test suite (from top level)
make testing
# Results in test/summary.xml

# MPI tests only
cd test/mpi
./configure --with-mpi=/path/to/mpich
make testing

# Command tests (mpicc, mpiexec, etc.)
cd test/commands
make testing

# Individual test execution
cd test/mpi/testsuite
./runtest -np 4 testname
```

### Test Categories
- **MPI tests**: `test/mpi/` - Core MPI functionality tests
- **Command tests**: `test/commands/` - Compiler and launcher tests
- **Hydra tests**: `test/hydra/` - Process manager tests

## Code Style Guidelines

### Formatting Rules
- **Indentation**: 4 spaces, no tabs
- **Line length**: Maximum 80 characters (absolute max: 100)
- **Brace style**: K&R with MPICH modifications
- **Spacing**: Space after casts, after for/if/while keywords
- **Comments**: First-column comments not auto-formatted

### Naming Conventions

#### Function/Variable Prefixes
```c
// MPI routines and common implementation
MPI_*, PMPI_*, MPIR_*, MPIU_*, MPID_*, MPIDI_*

// Process Manager Interface
PMI_*, PMIU_*, PMII_*

// ROMIO (MPI-IO) implementation
ADIO_*, ADIOI_*
```

#### Macro Naming
```c
// Internal features
MPIR_*, MPID_*, MPIU_*, MPIDU_*, MPICH_*, MPIO_*

// Generated by configure
HAVE_*, USE_*, NEEDS_*, WITH_*

// Header guards
#ifndef FILENAME_H_INCLUDED
#define FILENAME_H_INCLUDED
#endif
```

#### Variable Declaration Patterns
```c
// Input values
const int input_value;
const int *input_ptr;

// Output values
int *output_value;
int output_array[];
```

### Include Organization
1. Independent headers (no MPICH dependencies)
2. Forward declarations of MPIR structures
3. Device-independent headers
4. Device "pre" header
5. Device-dependent MPIR functionality
6. Device "post" header

### Error Handling Pattern
```c
int function_name(int in_arg, int *out_arg)
{
    int mpi_errno = MPI_SUCCESS;
    MPIDI_STATE_DECL(MPID_STATE_FUNC_NAME);

    MPIDI_FUNC_ENTER(MPID_STATE_FUNC_NAME);

    /* Input validation */
    MPIU_ERR_CHKANDJUMP(in_arg == 0, mpi_errno, MPI_ERR_OTHER, "**badarg");

    /* Function body */
    *out_arg = in_arg * 2;

    mpi_errno = some_internal_call();
    if (mpi_errno) MPIU_ERR_POP(mpi_errno);

fn_exit:
    MPIDI_FUNC_EXIT(MPID_STATE_FUNC_NAME);
    return mpi_errno;
fn_fail:
    /* Cleanup on error */
    goto fn_exit;
}
```

### Memory Management
```c
// Use MPICH memory macros everywhere
MPIU_Malloc(size)    // malloc replacement
MPIU_Calloc(n, size)  // calloc replacement
MPIU_Free(ptr)       // free replacement
MPIU_Realloc(ptr, size) // realloc replacement

// Persistent memory with cleanup
MPIU_CHKPMEM_DECL(2);
MPIU_CHKPMEM_MALLOC(ptr1, type*, size1, mpi_errno, "ptr1");
MPIU_CHKPMEM_MALLOC(ptr2, type*, size2, mpi_errno, "ptr2");
MPIU_CHKPMEM_COMMIT;  // Transfer responsibility

// Local memory (auto-freed)
MPIU_CHKLMEM_DECL(1);
MPIU_CHKLMEM_MALLOC(local_ptr, type*, size, mpi_errno, "local");
MPIU_CHKLMEM_FREEALL;
```

### String Handling
```c
// Use safe string functions
MPIU_Strncpy(dest, src, dest_size)  // Safer than strncpy
MPIU_Strnapp(dest, src, dest_size)  // Safer than strncat
MPIU_Snprintf(buf, size, fmt, ...)   // Portable vsnprintf
```

## Development Best Practices

### Performance Considerations
- Use `const`, `restrict`, and `register` qualifiers in hot paths
- Keep performance-critical function arguments ≤3
- Check common case first in conditionals
- Avoid function calls in tight loops when possible

### Portability Requirements
- Target C99 + POSIX 2001 features
- Use `#ifdef HAVE_FEATURE` for optional code
- Test with GCC 4.1+, Clang 3.0+, ICC 10.1+, PGI 9.0+
- Avoid compiler extensions unless properly guarded

### Code Structure
- Single return point per function (use fn_fail label)
- All functions return `int` error codes except trivial getters
- Document where allocated memory is freed
- Use `fn_exit`/`fn_fail` labels for error handling

### Testing Strategy
- All public functions must have test coverage
- Mark error handling code with coverage annotations:
```c
/* --BEGIN ERROR HANDLING-- */
if (error_condition) {
    MPIU_ERR_SETANDJUMP(mpi_errno, MPI_ERR_OTHER, "**fail");
}
/* --END ERROR HANDLING-- */
```

## Common Development Workflows

### Adding New MPI Function
1. Add function prototype to appropriate header
2. Implement in `src/mpi/` directory following error handling pattern
3. Add test case to appropriate testlist in `test/mpi/`
4. Update documentation if public API
5. Run `make testing` to verify
6. Run code cleanup script before commit

### Performance Optimization
1. Profile with `--enable-g=dbg` to identify hotspots
2. Add `restrict` qualifiers where aliasing impossible
3. Minimize memory allocations in hot paths
4. Use MPIU memory macros for debugging
5. Benchmark with test/performance/ benchmarks

### Debugging Memory Issues
```bash
# Configure with memory debugging
./configure --enable-g=mem,meminit

# Run with valgrind (if available)
valgrind --tool=memcheck mpiexec -n 2 ./test_program

# Memory corruption will be detected automatically
```
